# P2 Package Identity Migration Matrix

Status: identity flow and migration semantics confirmed on 2026-10-20. This is the implementation
contract for P2; it does not claim that every boundary has already been migrated.

## Identity Flow

| Boundary                           | Identity owner and userId source                                                                                        | Rule                                                                                                                                                                                                           |
|------------------------------------|-------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| UI package edit/save/clear         | DPIS installation owner; derive from the active app `Context`/application UID, not the selected target package          | Persist `(packageName, dpisOwnerUserId)`. The current-user app list/editor selects only this identity. Never infer the target app's user from its package name.                                                |
| Backup export                      | DPIS installation owner                                                                                                 | Export package values portably by package name. Do not serialize a source userId as import authority.                                                                                                          |
| Backup import                      | Importing DPIS installation owner                                                                                       | Bind every portable package entry to the importing user's identity. Ignore/reject any userId embedded in an untrusted backup.                                                                                  |
| Quick templates and global prefill | DPIS installation owner; Android-private stores                                                                         | Templates remain user-owned defaults. Applying one writes package config for the active DPIS user. Existing private template migration remains within that same user's stores.                                 |
| Modern runtime endpoint            | Calling injected Xposed host / Android user, as demonstrated by independent user-0 and user-999 Chrome remote snapshots | Keep the endpoint's user ownership explicit at the adapter. Do not assume a global endpoint or use UI's userId to identify a different target app. Verify snapshot identity against the injected process user. |
| Legacy target runtime read         | Not yet established for `XSharedPreferences`                                                                            | Track under P4. Do not infer target readability from UI self-hook readiness, and do not port Modern transport to Legacy for symmetry.                                                                          |
| App-process runtime lookup         | Injected target process UID, resolved to Android user                                                                   | Query only `(packageName, targetUidUserId)`. Missing/invalid identity fails closed; no user-0 fallback.                                                                                                        |
| system_server runtime lookup       | Activity/window/owner UID for the target package; `PackageUidResolver.userIdFromUid`                                    | Thread this target identity through snapshots, config source, properties, and runtime markers. Do not substitute the system_server host user or DPIS UI user.                                                  |
| LSPosed scope API                  | Calling DPIS user's service context; API 101 scope methods expose no user argument                                      | Keep scope/injection status distinct from saved package config. Do not treat scope rows as package config or infer an explicit target user from an API that does not expose one.                               |

## Migration Atomicity And Retry

- Copy recognized, valid fields into the owner-scoped staging namespace and write the owner-local
  completion marker in one archive transaction. Keep invalid/unknown source fields untouched; valid
  conflicts may be removed only in the same transaction that records their residual copy. The
  existing aggregate keys remain readable until the later reader/writer cutover.
- A crash before commit leaves the old archive authoritative. A crash after commit has both the
  staged destination and source; rerun preserves valid staged fields and completes any missing
  field. Migration is idempotent.
- Never set a completion marker after failed archive commit. A failed transaction writes neither
  staged values nor the marker. The marker records the owner `userId`; a mismatch is a failed
  ownership check, not permission to reassign the archive.
- `target_packages` alone never makes a package configured or runtime-active. Residual invalid
  values remain in place for diagnostics but are excluded from runtime snapshots. Unknown fields are
  never copied into staging.
- Keep the current `font.*` to `package_config.*` compatibility migration distinct from the new
  owner-scoped staging migration. Reuse its field registry/codecs, but change it only with focused
  merge/failure behavior tests.

## Delivery Stages

1. [x] Add the explicit `PackageIdentity` value and behavior tests; no persistence format change in
   that initial stage.
2. [x] Acquire the private archive owner user from `Context.applicationInfo.uid`; migrate fields
   idempotently into owner-scoped staging keys with per-field precedence. Keep current package-only
   readers/writers authoritative until cutover. The owner marker and staged fields commit
   atomically; reruns for the same owner scan for newly added fields, and a different owner fails
   closed. Invalid/unknown source values stay in the archive and are excluded from runtime/backup
   projection. Modern and Legacy full unit suites and Debug builds pass for this stage.
3. [x] Establish the owner-aware store boundary. Package reads prefer the current archive owner's
   scoped field and fall back to package-only compatibility keys; normal package writes mirror both
   representations in one transaction. App-list/editor and portable backup now use the active store
   owner, while backup payloads remain package-only and restore rebinds imported values to that
   owner. Backup rollback restores package-only data, scoped identity data, and the owner marker;
   rollback failure is surfaced explicitly. Runtime snapshot consumers and target UID lookup remain
   package-only and are deferred to the next stage.
4. [/] Thread target UID identity through app-process and system_server snapshot/lookup paths; prove
   absent targets fail closed without cross-user fallback. The shared snapshot owner contract,
   Modern app-process owner source, user-scoped property fallback, and existing system_server UID
   selection are implemented and unit-tested. Full system_server snapshot construction and device
   effectiveness remain open.
5. Track Legacy `XSharedPreferences` target-user readability separately under P4; do not change its
   transport by analogy.

Every stage updates only tests that assert a product invariant. Remove a prior test only when its
behavior is superseded, and retain tests for distinct migration or compatibility contracts.
